= Scopri la terminologia relativa ai volumi nel software SANtricity
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Scopri come i termini relativi al volume si applicano al tuo array di storage.



[[all-volume-types]]
== Tutti i tipi di volume

[cols="25h,~"]
|===
| Termine | Descrizione 


 a| 
Capacità assegnata
 a| 
Si utilizza la capacità allocata per creare volumi e per le operazioni dei servizi di copia.

La capacità allocata e la capacità segnalata coincidono per i volumi thick, ma sono diverse per i volumi thin. Per un volume thick, lo spazio fisicamente allocato è uguale allo spazio che viene segnalato all'host. Per un volume thin, la capacità segnalata è la capacità che viene segnalata agli host, mentre la capacità allocata è la quantità di spazio su disco attualmente allocata per la scrittura dei dati.



 a| 
Applicazione
 a| 
Un'applicazione è un software come SQL Server o Exchange. Si definiscono uno o più carichi di lavoro a supporto di ciascuna applicazione. Per alcune applicazioni, il sistema consiglia automaticamente una configurazione del volume che ottimizza lo storage. Caratteristiche come il tipo di I/O, la dimensione del segmento, la proprietà del controller e la cache di lettura e scrittura sono incluse nella configurazione del volume.



 a| 
Capacità
 a| 
La capacità è la quantità di dati che è possibile memorizzare in un volume.



 a| 
Proprietà del controller
 a| 
La proprietà del controller definisce il controller che è designato come controller proprietario, o primario, del volume. Un volume può avere un controller preferito (A o B) che "possiede" il volume. La proprietà del volume viene regolata automaticamente tramite la funzionalità di bilanciamento automatico del carico per correggere eventuali problemi di bilanciamento del carico quando i carichi di lavoro si spostano tra i controller. Il bilanciamento automatico del carico fornisce un bilanciamento automatico del carico di lavoro I/O e garantisce che il traffico I/O in entrata dagli host venga gestito e bilanciato dinamicamente tra entrambi i controller.



 a| 
Precaricamento dinamico della cache di lettura
 a| 
Il precaricamento dinamico della cache di lettura consente al controller di copiare ulteriori blocchi di dati sequenziali nella cache mentre legge i blocchi di dati da un'unità alla cache. Questo caching aumenta la probabilità che le future richieste di dati possano essere soddisfatte dalla cache. Il precaricamento dinamico della cache di lettura è importante per le applicazioni multimediali che utilizzano I/O sequenziale. La velocità e la quantità di dati precaricati nella cache si regolano automaticamente in base alla velocità e alla dimensione delle richieste di lettura dell'host. L'accesso casuale non comporta il precaricamento dei dati nella cache. Questa funzionalità non si applica quando il caching di lettura è disabilitato.

Per un volume thin, il precaricamento dinamico della cache di lettura è sempre disabilitato e non può essere modificato.



 a| 
Area di capacità libera
 a| 
Un'area di capacità libera è la capacità libera che può risultare dall'eliminazione di un volume o dal mancato utilizzo di tutta la capacità libera disponibile durante la creazione di un volume. Quando crei un volume in un gruppo di volumi che dispone di una o più aree di capacità libera, la capacità del volume è limitata all'area di capacità libera più grande in quel gruppo di volumi. Ad esempio, se un gruppo di volumi ha una capacità libera totale di 15 GiB e l'area di capacità libera più grande è di 10 GiB, il volume più grande che puoi creare è di 10 GiB.

Consolidando la capacità libera, puoi creare volumi aggiuntivi dalla quantità massima di capacità libera in un gruppo di volumi.



 a| 
Host
 a| 
Un host è un server che invia I/O a un volume su un array di storage.



 a| 
Cluster host
 a| 
Un cluster di host è un gruppo di host. Si crea un cluster di host per semplificare l'assegnazione degli stessi volumi a più host.



 a| 
hot spare drive
 a| 
Le unità hot spare sono supportate solo con i gruppi di volumi. Un'unità hot spare non contiene dati e funge da standby in caso di guasto di un'unità nei volumi RAID 1, RAID 3, RAID 5 o RAID 6 contenuti in un gruppo di volumi. L'unità hot spare aggiunge un ulteriore livello di ridondanza al tuo array di storage.



 a| 
LUN
 a| 
Un numero di unità logica (LUN) è il numero assegnato allo spazio di indirizzi che un host utilizza per accedere a un volume. Il volume viene presentato all'host come capacità sotto forma di LUN.

Ogni host dispone di un proprio spazio di indirizzamento LUN. Pertanto, lo stesso LUN può essere utilizzato da host diversi per accedere a volumi differenti.



 a| 
Scansione dei supporti
 a| 
Una scansione dei supporti di memorizzazione consente di rilevare gli errori dei supporti prima che vengano individuati durante una normale operazione di lettura o scrittura dai dischi. Una scansione dei supporti viene eseguita come operazione in background e analizza tutti i dati e le informazioni di ridondanza presenti nei volumi utente definiti.



 a| 
Spazio dei nomi
 a| 
Un namespace è una memoria NVM formattata per l'accesso a blocchi. È analogo a un'unità logica in SCSI, che corrisponde a un volume nell'array di storage.



 a| 
Pool
 a| 
Un pool è un insieme di unità disco raggruppate logicamente. È possibile utilizzare un pool per creare uno o più volumi accessibili a un host. (È possibile creare volumi da un pool o da un gruppo di volumi.)



 a| 
Capacità del pool o del gruppo di volumi
 a| 
La capacità di un pool, di un volume o di un gruppo di volumi è la capacità in un array di storage che è stata assegnata a un pool o a un gruppo di volumi. Questa capacità viene utilizzata per creare volumi e soddisfare le varie esigenze di capacità delle operazioni dei servizi di copia e degli oggetti di storage.



 a| 
cache di lettura
 a| 
La cache di lettura è un buffer che memorizza i dati letti dalle unità. I dati per un'operazione di lettura potrebbero essere già presenti nella cache da un'operazione precedente, eliminando la necessità di accedere alle unità. I dati rimangono nella cache di lettura finché non vengono svuotati.



 a| 
Capacità segnalata
 a| 
La capacità segnalata è la capacità che viene comunicata all'host e a cui l'host può accedere.

La capacità dichiarata e la capacità allocata coincidono per i volumi thick, ma sono diverse per i volumi thin. Per un volume thick, lo spazio fisicamente allocato è uguale allo spazio dichiarato all'host. Per un volume thin, la capacità dichiarata è la capacità dichiarata all'host, mentre la capacità allocata è la quantità di spazio su disco attualmente allocata per la scrittura dei dati.



 a| 
Dimensione del segmento
 a| 
Un segmento è la quantità di dati in kilobyte (KiB) che viene memorizzata su un'unità prima che l'array di storage si sposti sull'unità successiva nella striscia (gruppo RAID). La dimensione del segmento è uguale o inferiore alla capacità del gruppo di volumi. La dimensione del segmento è fissa e non può essere modificata per i pool.



 a| 
Striping
 a| 
Lo striping è un modo di memorizzare i dati sull'array di storage. Lo striping suddivide il flusso di dati in blocchi di una certa dimensione (chiamata "dimensione del blocco") e poi scrive questi blocchi sulle unità una alla volta. Questo modo di memorizzare i dati viene utilizzato per distribuire e archiviare i dati su più unità fisiche. Lo striping è sinonimo di RAID 0 e distribuisce i dati su tutte le unità di un gruppo RAID senza parità.



 a| 
Volume
 a| 
Un volume è un container in cui applicazioni, database e file system memorizzano i dati. È il componente logico creato per consentire all'host di accedere allo storage sull'array di storage.



 a| 
Assegnazione del volume
 a| 
L'assegnazione del volume è il modo in cui le LUN host vengono assegnate a un volume.



 a| 
Nome volume
 a| 
Il nome di un volume è una stringa di caratteri assegnata al volume al momento della sua creazione. È possibile accettare il nome predefinito oppure specificare un nome più descrittivo che indichi il tipo di dati memorizzato nel volume.



 a| 
Gruppo di volumi
 a| 
Un gruppo di volumi è un container per volumi con caratteristiche condivise. Un gruppo di volumi ha una capacità definita e livello RAID. È possibile utilizzare un gruppo di volumi per creare uno o più volumi accessibili a un host. (È possibile creare volumi da un gruppo di volumi o da un pool.)



 a| 
Carico di lavoro
 a| 
Un carico di lavoro è un oggetto di archiviazione che supporta un'applicazione. Puoi definire uno o più carichi di lavoro, o istanze, per applicazione. Per alcune applicazioni, il sistema configura il carico di lavoro per contenere volumi con caratteristiche di volume sottostanti simili. Queste caratteristiche di volume sono ottimizzate in base al tipo di applicazione che il carico di lavoro supporta. Ad esempio, se crei un carico di lavoro che supporta un'applicazione Microsoft SQL Server e poi crei volumi per quel carico di lavoro, le caratteristiche di volume sottostanti sono ottimizzate per supportare Microsoft SQL Server.



 a| 
cache di scrittura
 a| 
La cache di scrittura è un buffer che memorizza i dati provenienti dall'host che non sono ancora stati scritti sulle unità. I dati rimangono nella cache di scrittura finché non vengono scritti sulle unità. La cache di scrittura può aumentare le prestazioni di I/O.



 a| 
Caching della scrittura con mirroring
 a| 
La cache di scrittura con mirroring si verifica quando i dati scritti nella cache di un controller vengono scritti anche nella cache dell'altro controller. Pertanto, se un controller si guasta, l'altro può completare tutte le operazioni di scrittura in sospeso. Il mirroring della cache di scrittura è disponibile solo se la cache di scrittura è abilitata e sono presenti due controller. La cache di scrittura con mirroring è l'impostazione predefinita alla creazione del volume.



 a| 
Cache di scrittura senza batterie
 a| 
L'impostazione cache di scrittura senza batterie consente alla cache di scrittura di continuare anche quando le batterie sono mancanti, guaste, completamente scariche o non completamente cariche. La scelta della cache di scrittura senza batterie non è generalmente raccomandata, perché i dati potrebbero andare persi in caso di perdita di alimentazione. In genere, la cache di scrittura viene disattivata temporaneamente dal controller fino a quando le batterie non sono cariche o una batteria guasta viene sostituita.

|===


[[specific-to-thin-volumes]]
== Specifico per volumi thin

[NOTE]
====
System Manager non offre un'opzione per creare volumi thin. Se si desidera creare volumi thin, utilizzare la command line interface (CLI).

====
[NOTE]
====
I volumi con thin provisioning non sono disponibili sui sistemi storage EF600/EF600C o EF300/EF300C.

====
[cols="25h,~"]
|===
| Termine | Descrizione 


 a| 
Limite di capacità assegnata
 a| 
Il limite di capacità allocata è il limite massimo su quanto può crescere la capacità fisica allocata per un volume thin.



 a| 
Capacità scritta
 a| 
La capacità scritta è la quantità di capacità che è stata scritta dalla capacità riservata allocata per i volumi sottili.



 a| 
Soglia di attenzione
 a| 
È possibile impostare una soglia di avviso che verrà emessa quando la capacità allocata per un volume thin raggiunge la percentuale di riempimento (la soglia di avviso).
