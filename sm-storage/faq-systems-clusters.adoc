= Domande frequenti sui sistemi host e cluster host per SANtricity System Manager
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Questa FAQ può esserti utile se stai cercando una risposta rapida a una domanda.



== Che cosa sono gli host e i cluster di host?

Un host è un server che invia operazioni di I/O a un volume su un array di storage. Un cluster di host è un gruppo di host. Si crea un cluster di host per semplificare l'assegnazione degli stessi volumi a più host.

Definisci un host separatamente. Può essere un'entità indipendente oppure essere aggiunto a un cluster di host. Puoi assegnare volumi a un singolo host, oppure un host può far parte di un cluster di host che condivide l'accesso a uno o più volumi con altri host nel cluster di host.

Il cluster host è un'entità logica che si crea in SANtricity System Manager. È necessario aggiungere gli host al cluster host prima di poter assegnare i volumi.



== Perché dovrei creare un cluster host?

È necessario creare un cluster di host se si desidera che due o più host condividano l'accesso allo stesso set di volumi. Normalmente, sui singoli host è installato un software di clustering per coordinare l'accesso ai volumi.



== Come faccio a sapere quale tipo di sistema operativo host è corretto?

Il campo Tipo di sistema operativo host contiene il sistema operativo dell'host. Puoi selezionare il tipo di host consigliato dall'elenco a discesa.

I tipi di host visualizzati nell'elenco a discesa dipendono dal modello dell'array di storage e dalla versione del firmware. Le versioni più recenti mostrano per prime le opzioni più comuni, che sono le più probabilmente appropriate. La presenza in questo elenco non implica che l'opzione sia completamente supportata.

== Cosa sono gli HBA e le porte adapter?

Un adattatore bus host (HBA) è una scheda che risiede in un host e contiene una o più porte host. Una porta host è una porta su un adattatore bus host (HBA) che fornisce la connessione fisica a un controller e viene utilizzata per le operazioni di I/O.

Le porte dell'adattatore sull'HBA sono chiamate porte host. La maggior parte degli HBA ha una o due porte host. L'HBA ha un World Wide Identifier (WWID) univoco e ogni porta host dell'HBA ha un WWID univoco. Gli identificatori delle porte host vengono utilizzati per associare l'HBA appropriato all'host fisico quando si crea manualmente l'host tramite SANtricity System Manager.



== Come faccio ad associare le porte host a un host?

Se si crea manualmente un host, è necessario innanzitutto utilizzare l'apposita utility per l'host bus adapter (HBA) disponibile sull'host per determinare gli identificatori della porta host associati a ciascun HBA installato nell'host.

Quando si dispone di queste informazioni, selezionare gli identificatori della porta host che hanno effettuato l'accesso all'array di storage dall'elenco fornito nella finestra di dialogo Crea host.

[NOTE]
====
Assicurati di selezionare gli identificatori di porta host appropriati per l'host che stai creando. Se associ gli identificatori di porta host errati, potresti causare un accesso indesiderato da parte di un altro host a questi dati.

====


== Come si creano i segreti CHAP?

Se si configura l'autenticazione Challenge Handshake Authentication Protocol (CHAP) su qualsiasi host iSCSI connesso all'array di storage, è necessario reinserire quel segreto CHAP dell'initiator per ciascun host iSCSI.

Per fare ciò, puoi utilizzare System Manager sia come parte dell'operazione Create Host sia tramite l'opzione View/Edit Settings.

Se si utilizza l'autenticazione reciproca CHAP, è necessario definire anche un segreto CHAP di destinazione per l'array di storage nella pagina Impostazioni e reinserire tale segreto CHAP di destinazione su ciascun host iSCSI.



== Qual è il cluster predefinito?

Il cluster predefinito è un'entità definita dal sistema che consente a qualsiasi identificatore di porta host non associato che abbia effettuato l'accesso all'array di storage di accedere ai volumi assegnati al cluster predefinito. Un identificatore di porta host non associato è una porta host che non è logicamente associata a un host specifico, ma è fisicamente installata in un host e ha effettuato l'accesso all'array di storage.

[NOTE]
====
Se si desidera che gli host abbiano accesso specifico a determinati volumi nell'array di storage, non si deve utilizzare il cluster predefinito. È invece necessario associare gli identificatori di porta degli host ai rispettivi host. Questa operazione può essere eseguita manualmente durante l'operazione di creazione dell'host. Successivamente, si assegnano i volumi a un singolo host o a un cluster di host.

====
Dovresti utilizzare _solo_ il cluster predefinito in situazioni particolari in cui l'ambiente di storage esterno consente a tutti gli host e a tutti gli identificatori di porta host connessi all'array di storage di accedere a tutti i volumi (modalità all-access) senza dover necessariamente rendere noti gli host all'array di storage o all'interfaccia utente.

Inizialmente, è possibile assegnare volumi solo al cluster predefinito tramite l'interfaccia a riga di comando (CLI). Tuttavia, dopo aver assegnato almeno un volume al cluster predefinito, questa entità (denominata Default Cluster) viene visualizzata nell'interfaccia utente, dove è possibile gestire questa entità.



== Che cos'è la segnalazione della connettività host?

Quando la segnalazione della connettività host è abilitata, l'array di storage monitora continuamente la connessione tra i controller e gli host configurati e ti avvisa se la connessione viene interrotta.

Potrebbero verificarsi interruzioni della connessione in caso di cavo allentato, danneggiato o mancante, oppure in presenza di altri problemi con l'host. In queste situazioni, il sistema potrebbe visualizzare un messaggio di Recovery Guru:

* *Ridondanza host persa* -- Si apre se uno dei controller non può comunicare con l'host.
* *Tipo host non corretto* -- Si apre se il tipo dell'host è specificato in modo errato sull'array di storage, il che potrebbe causare problemi di failover.


Potrebbe essere opportuno disabilitare la segnalazione della connettività host in situazioni in cui il riavvio di un controller potrebbe richiedere più tempo del timeout di connessione. La disabilitazione di questa funzione sopprime i messaggi di Recovery Gurus.

[NOTE]
====
La disabilitazione della segnalazione della connettività host disabilita anche il bilanciamento del carico automatico, che monitora e bilancia l'utilizzo delle risorse del controller. Tuttavia, se si riabilita la segnalazione della connettività host, la funzionalità di bilanciamento del carico automatico non viene riattivata automaticamente.
