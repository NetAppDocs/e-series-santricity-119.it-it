= Come funzionano i carichi di lavoro nel software SANtricity
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Quando si crea un volume, si seleziona un workload per personalizzare la configurazione dell'array di storage per una specifica applicazione.

Un carico di lavoro è un oggetto di archiviazione che supporta un'applicazione. Puoi definire uno o più carichi di lavoro, o istanze, per applicazione. Per alcune applicazioni, il sistema configura il carico di lavoro per contenere volumi con caratteristiche di volume sottostanti simili. Queste caratteristiche di volume sono ottimizzate in base al tipo di applicazione che il carico di lavoro supporta. Ad esempio, se crei un carico di lavoro che supporta un'applicazione Microsoft SQL Server e poi crei volumi per quel carico di lavoro, le caratteristiche di volume sottostanti sono ottimizzate per supportare Microsoft SQL Server.

Durante la creazione del volume, il sistema richiede di rispondere a domande sull'utilizzo del carico di lavoro. Ad esempio, se si stanno creando volumi per Microsoft Exchange, viene chiesto di quante caselle di posta si ha bisogno, quali sono i requisiti medi di capacità delle caselle di posta e quante copie del database si desiderano. Il sistema utilizza queste informazioni per creare una configurazione di volume ottimale per te, che può essere modificata secondo necessità. Facoltativamente, è possibile saltare questo passaggio nella sequenza di creazione del volume.



[[types-of-workloads]]
== Tipi di carichi di lavoro

È possibile creare due tipi di carichi di lavoro: specifici per applicazioni e altri.

* *Specifico per l'applicazione*. Quando si creano volumi utilizzando un carico di lavoro specifico per un'applicazione, il sistema può consigliare una configurazione del volume ottimizzata per ridurre al minimo la contesa tra l'I/O del carico di lavoro dell'applicazione e altro traffico proveniente dall'istanza dell'applicazione. Le caratteristiche del volume, come il tipo di I/O, la dimensione del segmento, la proprietà del controller e la cache di lettura e scrittura, vengono automaticamente consigliate e ottimizzate per i carichi di lavoro creati per i seguenti tipi di applicazione.
+
** Microsoft® SQL Server™
** Microsoft® server Exchange™
** Applicazioni di videosorveglianza
** VMware ESXi™ (per volumi da utilizzare con Virtual Machine File System)
+
È possibile esaminare la configurazione del volume consigliata e modificare, aggiungere o eliminare i volumi e le caratteristiche consigliati dal sistema utilizzando la finestra di dialogo Add/Edit Volumes.



* *Altro* (o applicazioni senza supporto specifico per la creazione di volumi). Altri carichi di lavoro utilizzano una configurazione di volume che è necessario specificare manualmente quando si desidera creare un carico di lavoro non associato a una specifica applicazione o se il sistema non dispone di ottimizzazione integrata per l'applicazione che si intende utilizzare sull'array di storage. È necessario specificare manualmente la configurazione del volume tramite la finestra di dialogo Aggiungi/Modifica volumi.




[[application-and-workload-views]]
== Viste dell'applicazione e del carico di lavoro

Per visualizzare applicazioni e carichi di lavoro, avvia SANtricity System Manager. Da tale interfaccia, puoi visualizzare le informazioni associate a un carico di lavoro specifico di un'applicazione in diversi modi:

* È possibile selezionare la scheda *Applications & Workloads* nel riquadro Volumi per visualizzare i volumi dell'array di storage raggruppati per carico di lavoro e per tipo di applicazione a cui il carico di lavoro è associato.
* È possibile selezionare la scheda *Applications & Workloads* nel riquadro Prestazioni per visualizzare le metriche delle prestazioni (latenza, IOPS e MB) per gli oggetti logici. Gli oggetti sono raggruppati per applicazione e carico di lavoro associato. Raccogliendo questi dati sulle prestazioni a intervalli regolari, è possibile stabilire parametri di riferimento e analizzare le tendenze, il che può essere utile durante l'indagine di problemi relativi alle prestazioni di I/O.
