= Configura l'accesso remoto (SSH) in SANtricity System Manager
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Abilitando l'accesso remoto, si consente agli utenti esterni alla rete locale di avviare una sessione SSH e accedere alle impostazioni del controller.

Per le versioni di SANtricity 11.74 e successive, puoi anche configurare l'autorizzazione multifattore (MFA) richiedendo agli utenti di inserire una chiave SSH e/o una password SSH. Per le versioni di SANtricity 11.73 e precedenti, questa funzionalità _non_ include un'opzione per l'autorizzazione multifattore con chiavi SSH e password.

[CAUTION]
====
*Rischio per la sicurezza* -- Per motivi di sicurezza, solo il personale di supporto tecnico dovrebbe utilizzare la funzione di accesso remoto.

====
.Passaggi
. Seleziona *Hardware*.
. Se il grafico mostra le unità, fare clic sulla scheda *Controllers & Components*.
+
La grafica cambia per mostrare i controller anziché le unità.

. Fai clic sul controller per cui desideri configurare l'accesso remoto.
+
Viene visualizzato il menu contestuale del controller.

. Selezionare *Configura accesso remoto (SSH)*. (Per SANtricity versioni 11.73 e precedenti, questa voce di menu è *Modifica accesso remoto*.)
+
Si apre la finestra di dialogo per abilitare l'accesso remoto.

. Seleziona la casella di controllo *Abilita accesso remoto*.
+
Questa impostazione consente l'accesso remoto con tre opzioni di autorizzazione:

+
** *Solo password*. Per questa opzione, hai finito e puoi cliccare su *Salva*. Se disponi di un sistema duplex, puoi abilitare l'accesso remoto sul secondo controller seguendo i passaggi precedenti.
** *Chiave SSH o password*. Per questa opzione, procedi al passaggio successivo.
** *Sia la password che la chiave SSH*. Per questa opzione, selezionare la casella di controllo *Richiedi chiave pubblica e password autorizzate per l'accesso remoto* e procedere al passaggio successivo.


. Compila il campo *Authorized public key*. Questo campo contiene un elenco di chiavi pubbliche autorizzate, nel formato del file *authorized_keys* di OpenSSH.
+
Quando si compila il campo *Authorized public key*, tenere presente le seguenti linee guida:

+
** Il campo *Chiave pubblica autorizzata* si applica a entrambi i controller e deve essere configurato solo sul primo controller.
** Il file *authorized_keys* deve contenere una sola chiave per riga. Le righe che iniziano con # e le righe vuote vengono ignorate. Per ulteriori informazioni sul formato del file, vedere link:https://www.ssh.com/academy/ssh/authorized-keys-openssh["Configurazione delle chiavi autorizzate per OpenSSH"^].
** Un file *authorized_keys* dovrebbe avere un aspetto simile al seguente esempio:
+
[listing]
----
ssh-rsa
AAAAB3NzaC1yc2EAAAADAQABAAABAQDJlG20rYTk4ok+xFjkPHYp/R0LfJqEYDLXA5AJ49w3DvAWLrUg+1CpNq76WSqmQBmoG9jgbcAB5ABGdswdeMQZHilJcu29iJ3OKKv6SlCulAj1tHymwtbdhPuipd2wIDAQAB
----


. Quando hai finito, fai clic su *Save*.
. Per i sistemi duplex, puoi abilitare l'accesso remoto sul secondo controller seguendo i passaggi sopra. Se configuri l'opzione sia per la password che per la chiave SSH, assicurati di selezionare nuovamente la casella di controllo *Require authorized public key and password for remote login*.
. Dopo che il supporto tecnico ha completato la risoluzione dei problemi, puoi disabilitare l'accesso remoto tornando alla finestra di dialogo Configura accesso remoto e deselezionando la casella di controllo *Abilita accesso remoto*. Se l'accesso remoto è abilitato su un secondo controller, si apre una finestra di dialogo di conferma che consente di disabilitare l'accesso remoto anche su quest'ultimo.
+
La disabilitazione dell'accesso remoto termina tutte le sessioni SSH attive e rifiuta qualsiasi nuova richiesta di accesso.
