= Domande frequenti sul mirroring asincrono per SANtricity System Manager
:allow-uri-read: 
:experimental: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Questa FAQ può esserti utile se stai cercando una risposta rapida a una domanda.



== In che modo il mirroring asincrono si differenzia dal mirroring sincrono?

La funzione di mirroring asincrono si differenzia dalla funzione di mirroring sincrono per un aspetto fondamentale: acquisisce lo stato del volume sorgente in un determinato momento e copia solo i dati che sono cambiati dall'ultima acquisizione dell'immagine.

Con il mirroring sincrono, lo stato del volume primario non viene acquisito in un determinato momento, ma riflette tutte le modifiche apportate al volume primario sul volume secondario. Il volume secondario è identico al volume primario in ogni istante perché, con questo tipo di mirroring, ogni volta che viene eseguita una scrittura sul volume primario, viene eseguita una scrittura anche sul volume secondario. L'host non riceve una conferma dell'avvenuta scrittura finché il volume secondario non viene aggiornato correttamente con le modifiche apportate al volume primario.

Con il mirroring asincrono, l'array di storage remoto non è completamente sincronizzato con l'array di storage locale, quindi se l'applicazione deve passare all'array di storage remoto a causa della perdita dell'array di storage locale, alcune transazioni potrebbero andare perse.

Confronto tra le funzionalità di mirroring:

[cols="1a,1a"]
|===
| Mirroring asincrono | Mirroring sincrono 


 a| 
*Metodo di replica*



 a| 
* *Point-in-Time*
+
Il mirroring viene eseguito su richiesta o automaticamente in base a una pianificazione definita dall'utente. Le pianificazioni possono essere definite con una granularità di minuti. Il tempo minimo tra le sincronizzazioni è di 10 minuti.


 a| 
* *Continuo*
+
Il mirroring viene eseguito automaticamente in modo continuo, copiando i dati da ogni scrittura dell'host.





 a| 
*Capacità riservata*



 a| 
* *Multipli*
+
È necessario un volume di capacità riservata per ogni coppia speculare.


 a| 
* *Singolo*
+
È richiesto un unico volume di capacità riservata per tutti i volumi mirrorati.





 a| 
*Comunicazione*



 a| 
* *iSCSI e Fibre Channel*
+
Supporta le interfacce iSCSI e Fibre Channel tra gli array di storage.


 a| 
* *Fibre Channel*
+
Supporta solo interfacce Fibre Channel tra gli array di storage.





 a| 
*Distanza*



 a| 
* *Illimitato*
+
Supporto per distanze praticamente illimitate tra l'array di storage locale e l'array di storage remoto, con la distanza in genere limitata solo dalle capacità della rete e dalla tecnologia di estensione del canale.


 a| 
* *Limitato*
+
In genere deve trovarsi entro circa 10 km (6.2 miglia) dall'array di storage locale per soddisfare i requisiti di latenza e prestazioni dell'applicazione.



|===


== Perché non posso accedere alla funzione di mirroring che ho scelto?

Il mirroring viene configurato nell'interfaccia SANtricity Unified Manager.

[NOTE]
====
La funzione di mirroring sincrono non è disponibile sull'array di storage EF600/EF600C o EF300/EF300C.

====
Per abilitare e configurare il mirroring tra due array, verificare quanto segue:

* Il servizio Web Services Proxy deve essere in esecuzione. (Unified Manager è installato su un sistema host insieme al Web Services Proxy.)
* Unified Manager deve essere in esecuzione sul tuo host locale tramite una connessione HTTPS.
* I due storage array che si desidera utilizzare per il mirroring devono essere rilevati in Unified Manager.
* Unified Manager deve disporre di certificati SSL validi per gli array di storage. È possibile accettare un certificato autofirmato o installare certificati firmati da CA tramite Unified Manager.


Per le istruzioni di configurazione, vedere quanto segue:

* link:../um-manage/create-asynchronous-mirrored-pair-um.html["Creare una coppia speculare asincrona (in Unified Manager)"]
* link:../um-manage/create-synchronous-mirrored-pair-um.html["Creare una coppia sincrona mirrorata (in Unified Manager)"]




== Cosa devo sapere prima di creare un mirror consistency group?

Segui queste linee guida prima di creare un mirror consistency group.

[NOTE]
====
La funzione di mirroring sincrono non è disponibile sui sistemi storage EF600/EF600C o EF300/EF300C.

====
Si crea un gruppo di coerenza in Unified Manager nella procedura guidata Crea coppie speculari.

Soddisfare i seguenti requisiti per Unified Manager:

* Il servizio Web Services Proxy deve essere in esecuzione.
* Unified Manager deve essere in esecuzione sul tuo host locale tramite una connessione HTTPS.
* Unified Manager deve visualizzare certificati SSL validi per lo storage array. È possibile accettare un certificato autofirmato o installare un certificato di sicurezza personalizzato tramite Unified Manager e accedendo a menu:Certificate[Certificate Management].


Assicurati inoltre di soddisfare i seguenti requisiti per gli array di storage:

* I due array di storage devono essere rilevati in Unified Manager.
* Ogni array di storage deve avere due controller.
* Ciascun controller, sia nell'array primario che in quello secondario, deve avere una porta di gestione Ethernet configurata e deve essere connesso alla rete.
* Gli array di storage hanno una versione minima del firmware pari a 7.84. (Ciascuno può eseguire diverse versioni del sistema operativo.)
* È necessario conoscere la password per gli array di storage locali e remoti.
* I tuoi array di storage locali e remoti sono collegati tramite una fabric Fibre Channel o un'interfaccia iSCSI.




== Mirroring asincrono - Cosa devo sapere prima di creare una coppia speculare?

Si configurano le coppie di mirror nell'interfaccia SANtricity Unified Manager e poi si gestiscono le coppie in SANtricity System Manager.

Prima di creare una coppia speculare, seguire queste linee guida.

* È necessario disporre di due storage array.
* Ogni array di storage deve avere due controller.
* Ciascun controller, sia nell'array primario che in quello secondario, deve avere una porta di gestione Ethernet configurata e deve essere connesso alla rete.
* I tuoi array di storage locali e remoti sono collegati tramite una fabric Fibre Channel o un'interfaccia iSCSI.
* Gli array di storage hanno una versione minima del firmware pari a 7.84. (Ciascuno può eseguire diverse versioni del sistema operativo.)
* È necessario conoscere la password per gli array di storage locali e remoti.
* È necessario disporre di una capacità libera sufficiente sull'array di storage remoto per creare un volume secondario uguale o superiore al volume primario che si desidera replicare.
* Hai installato Web Services Proxy e Unified Manager. Le coppie speculari sono configurate nell'interfaccia di Unified Manager.
* I due array di storage vengono rilevati in Unified Manager.
* L'array di storage deve contenere almeno un mirror consistency group. Si crea un mirror consistency group in Unified Manager nella procedura guidata Create Mirrored Pairs.




== Cosa devo sapere prima di aumentare la capacità riservata su un volume di coppia in mirroring?

In genere, si dovrebbe aumentare la capacità riservata quando si riceve un avviso che la capacità riservata per una coppia di mirroring sta per esaurirsi. È possibile aumentare la capacità riservata solo in incrementi di 8 GiB.

Per le operazioni di mirroring asincrono, la capacità riservata è in genere il 20 percento del volume di base. Scegli una capacità maggiore per la capacità riservata se esiste una o entrambe queste condizioni:

* Intendi mantenere la coppia mirrorata per un lungo periodo di tempo.
* Una percentuale elevata di blocchi di dati subirà modifiche sul volume primario a causa di un'intensa attività di I/O. Utilizza i dati storici sulle prestazioni o altre utilità del sistema operativo per aiutarti a determinare l'attività di I/O tipica sul volume primario.


È possibile aumentare la capacità riservata per una coppia di mirroring eseguendo una delle seguenti azioni:

* Regola la percentuale di capacità per un volume della coppia in mirroring selezionando menu:Storage[Pools and Volumes Groups] e poi facendo clic sulla scheda *Reserved Capacity*.
* Crea un nuovo volume utilizzando la capacità libera disponibile in un pool o in un gruppo di volumi.
+
Se non esiste capacità libera in alcun pool o gruppo di volumi, è possibile aggiungere capacità non configurata sotto forma di unità non utilizzate a un pool o gruppo di volumi.





== Perché non posso aumentare la capacità riservata con la quantità richiesta?

È possibile aumentare la capacità riservata solo in incrementi di 4 GiB.

Esaminare le seguenti linee guida:

* È necessario disporre di una capacità libera sufficiente nel pool o nel gruppo di volumi affinché possa essere espanso se necessario.
+
Se non esiste capacità libera in alcun pool o gruppo di volumi, è possibile aggiungere capacità non assegnata sotto forma di unità non utilizzate a un pool o gruppo di volumi.

* Il volume nel pool o nel gruppo di volumi deve avere uno stato Ottimale e non deve essere in alcuno stato di modifica.
* La capacità libera deve esistere nel pool o nel gruppo di volumi che si desidera utilizzare per aumentare la capacità.


Per le operazioni di mirroring asincrono la capacità riservata è in genere il 20 percento del volume di base. Utilizzare una percentuale più alta se si ritiene che il volume di base subirà molte modifiche o se la durata stimata dell'operazione di copy service di un oggetto storage sarà molto lunga.



== Perché dovrei cambiare questa percentuale?

La capacità riservata è in genere pari al 40 percento del volume di base per le operazioni di snapshot e al 20 percento del volume di base per le operazioni di mirroring asincrono.

Di solito questa capacità è sufficiente. La capacità necessaria varia a seconda della frequenza e delle dimensioni delle scritture di I/O sul volume di base e di quanto tempo si intende utilizzare l'operazione di servizio di copia dell'oggetto di storage.

In generale, scegli una percentuale maggiore per la capacità riservata se sussistono una o entrambe queste condizioni:

* Se la durata dell'operazione di copy service di un particolare oggetto storage sarà molto lunga.
* Se una grande percentuale di blocchi di dati cambierà sul volume di base a causa di un'intensa attività di I/O. Utilizzare i dati storici sulle prestazioni o altre utility del sistema operativo per aiutare a determinare l'attività di I/O tipica del volume di base.




== Perché vedo più di un candidato a capacità riservata?

Se in un pool o gruppo di volumi è presente più di un volume che soddisfa la percentuale di capacità selezionata per l'oggetto storage, verranno visualizzati più candidati.

È possibile aggiornare l'elenco dei candidati consigliati modificando la percentuale di spazio fisico dell'unità che si desidera riservare sul volume di base per le operazioni di copy service. I candidati migliori vengono visualizzati in base alla selezione effettuata.



== Perché vedo valori Non disponibili visualizzati nella tabella?

La tabella elenca i valori Not Available quando i dati presenti sull'array di storage remoto non sono disponibili per essere visualizzati.

Per visualizzare i dati dell'array di storage remoto, avvia System Manager da Unified Manager.



== Perché non vedo tutti i miei pool e gruppi di volumi?

Quando si crea un volume secondario per la coppia di mirroring asincrono, il sistema visualizza un elenco di tutti i pool e i gruppi di volumi idonei per quella coppia di mirroring asincrono. Qualsiasi pool o gruppo di volumi non idoneo all'uso non viene visualizzato in quell'elenco.

I pool o i gruppi di volumi potrebbero non essere idonei per uno dei seguenti motivi.

* Le capacità di sicurezza di un pool o di un gruppo di volumi non corrispondono.
* Un pool o un gruppo di volumi è in uno stato non ottimale.
* La capacità di un pool o di un gruppo di volumi è troppo piccola.




== Mirroring asincrono - Perché non vedo tutti i volumi?

Quando si seleziona un volume primario per una coppia con mirroring, un elenco mostra tutti i volumi idonei.

I volumi che non sono idonei all'uso non vengono visualizzati in quell'elenco. I volumi potrebbero non essere idonei per uno dei seguenti motivi:

* Il volume non è ottimale.
* Il volume partecipa già a una relazione di mirroring.
* Per i volumi sottili, l'auto-espansione deve essere abilitata.



NOTE: Per i controller EF600 e EF300, i volumi primari e secondari di una coppia asincrona in mirroring devono corrispondere allo stesso protocollo, livello di vassoio, dimensione del segmento, tipo di sicurezza e livello RAID. Le coppie asincrone in mirroring non ammissibili non appariranno nell'elenco dei volumi disponibili.



== Mirroring asincrono - Perché non vedo tutti i volumi sull'array di storage remoto?

Quando si seleziona un volume secondario sull'array di storage remoto, un elenco mostra tutti i volumi idonei per quella coppia di mirroring.

Qualsiasi volume che non è idoneo all'uso non viene visualizzato in quell'elenco. I volumi potrebbero non essere idonei per uno dei seguenti motivi:

* Il volume non è ottimale.
* Il volume partecipa già a una relazione di mirroring.
* Gli attributi del volume sottile tra il volume primario e il volume secondario non corrispondono.
* Se si utilizza Data Assurance (DA), il volume primario e il volume secondario devono avere le stesse impostazioni DA.
+
** Se il volume primario è abilitato per DA, il volume secondario deve essere abilitato per DA.
** Se il volume primario non è abilitato per DA, il volume secondario non deve essere abilitato per DA.






== Perché dovrei aggiornare l'indirizzo IP del mio array di storage remoto?

Aggiornare l'indirizzo IP dell'array di storage remoto quando l'indirizzo IP di una porta iSCSI cambia e l'array di storage locale non è in grado di comunicare con l'array di storage remoto.

Quando si stabilisce una relazione di mirroring asincrono con una connessione iSCSI, sia l'array di storage locale che quello remoto memorizzano un record dell'indirizzo IP dell'array di storage remoto nella configurazione di mirroring asincrono. Se l'indirizzo IP di una porta iSCSI cambia, l'array di storage remoto che tenta di utilizzare tale porta riscontra un errore di comunicazione.

L'array di storage con l'indirizzo IP modificato invia un messaggio a ciascun array di storage remoto associato ai gruppi di coerenza mirror configurati per il mirroring su una connessione iSCSI. Gli array di storage che ricevono questo messaggio aggiornano automaticamente il proprio indirizzo IP di destinazione remoto.

Se l'array di storage con l'indirizzo IP modificato non riesce a inviare il messaggio inter-array a un array di storage remoto, il sistema invia un avviso relativo al problema di connettività. Utilizza l'opzione Aggiorna indirizzo IP remoto per ristabilire la connessione con l'array di storage locale.
